Cluster-level simulation
Each AZ contains named ESX hosts. Affinity rules automatically place VMs; no ESX host pinning. One host per AZ is reserved from aggregate CPU and memory for N+1 maintenance; all hosts remain visible for placement. ESXi overhead is not deducted. Host logical cores are calculated from socket topology; VM CPU counts correspond to vCPUs.

Region placement board

Move VMs between AZs. Host placement is automatic; switch affinity rules on or off below.

Rule details

When enabled, these limits apply across both Kubernetes clusters within each AZ:

  1. Etcd separation: At most one etcd VM per ESX host. It may share with other VM types.
  2. Master/ingress pairing: Matching node numbers within the same Kubernetes cluster stay together, such as master-01 and ingress-01. Moving either to another AZ moves its partner too.
  3. Pair separation: At most one master/ingress pair per ESX host.
  4. Workers with a pair: At most one worker on a host containing a master/ingress pair.
  5. Other workers: At most two workers on a host without a master/ingress pair.

Turning off: Immediately redistributes all VMs across the hosts in their current AZs without pairing, etcd separation, or per-host VM count limits. Previously unplaced VMs can be assigned. VM counts, sizes, and cluster labels are retained. Capacity warnings and NUMA estimates remain active.

Turning on: Recalculates placement under all five rules. Ingress VMs follow their matching master’s AZ. VMs that cannot satisfy the rules remain visible as unplaced. This does not restore the previous host arrangement.

ESX hosts are assigned automatically in both modes; VMs are never pinned to a host.
